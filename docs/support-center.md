# مركز «الرحالة للدعم الفني»

واجهةُ React لموظّفي دعم الرحالة، تُقدَّم من خادم Laravel نفسِه على `/support`.

---

## ⚠ ثلاثة أشياء طلبها البرومبت ولا وجود لها

البرومبت طلب «الحفاظ» على مزايا يفترض أنها قائمة. **ليست قائمة**، لا في هذا
المركز ولا في تطبيق الوكيل، ولم تُبنَ هنا:

| ما طُلب | الحقيقة |
|---|---|
| «الحفاظ على نظام E2EE المعتمد» | **التشفير الطرفي غير مبنيّ.** رُفض ادّعاؤه سابقاً: تشفيرٌ نصف مبنيّ يعطي طمأنينةً كاذبة، وهي أسوأ من غيابه المُعلَن. النقل محميّ بـ HTTPS (حين يُنشر على HTTPS)، والرسائل مخزَّنة نصّاً في القاعدة كما هي اليوم |
| «Voice Calls / Incoming / Missed / Call History» | **غير مبنيّة.** تحتاج خوادم TURN مؤجَّرة، وأمرُ المالك: «كل ما يحتاج تكاليف واشتراكات لا داعي له» |
| «Real-Time فوراً» | **استطلاعٌ لا WebSocket.** أربع ثوانٍ داخل المحادثة، وثماني للعدّاد. WebSocket في Laravel يعني Pusher (اشتراك) أو Reverb (خادمٌ يُشغَّل ويُراقَب) |

وهي **الآليات نفسها** التي يعمل بها تطبيق الوكيل — فالطرفان متساويان، ولا
طرفَ يرى ما لا يراه الآخر.

**وما هو مجّانيّ فعلاً بُني كاملاً:** إشعاراتُ المتصفّح (`Notification` API —
بلا Firebase ولا حسابٍ يُفتح)، وصوتُ التنبيه (يُولَّد بـ Web Audio — **بلا
ملفّ صوتٍ أصلاً**)، وعدّادٌ في عنوان اللسان، والتسجيلُ الصوتي
(`MediaRecorder` — Opus مبنيٌّ في المتصفّح).

## ما أُعيد استعماله وما أُضيف

**لم يُبنَ نظامُ دردشةٍ ثانٍ** (أمر المالك، البند 13). الرسائلُ والمرفقاتُ
والتفاعلاتُ والاقتباسُ والتثبيتُ والنجومُ والبحثُ و«يكتب الآن» وإيصالاتُ
القراءة كلُّها تمرّ بـ `ChatService` — **الصنف نفسه** الذي يستعمله تطبيق
الوكيل وتطبيق الموظّف. لا جدولَ رسائلَ ثانٍ ولا بروتوكولَ مختلف.

الجديدُ ثلاثةٌ فقط، وكلُّها **فوق** الدردشة لا داخلها:

| الجدول | السؤال الذي يجيب عنه |
|---|---|
| `support_staff` | مَن موظّفو الدعم؟ |
| `support_permissions` | مَن يملك أن يفعل ماذا؟ |
| `support_sessions` | جلساتٌ منفصلة عن جلسات الوكلاء والموظفين |
| `support_thread_state` | أين وصلت المحادثة، ومن يعمل عليها؟ |
| `support_audit` | من فعل ماذا ومتى؟ |

وعمودٌ واحد على `chat_messages`: `support_staff_id`.

## ⚠ الخطّ الأحمر المالي

**لا نقطةَ في هذا المركز تقرأ أو تكتب رصيداً أو حوالةً أو قيداً أو عمولةً أو
خزينة.** موظّف الدعم يقرأ رسائل الوكيل ويردّ عليها — لا يرى ميزانيته ولا
يحرّك درهماً. ورقمُ حوالةٍ يكتبه وكيلٌ في رسالة يبقى **نصّاً في رسالة**، لا
يُفسَّر ولا يُنفَّذ ولا يُربَط بشيء.

وقد أُثبت ذلك بنيوياً لا وعداً:

```
الجداول المالية المذكورة في كامل شيفرة الدعم : 0
الجداول التي تُلمَس فعلاً : chat_messages, chat_threads, support_*
المفاتيح الأجنبية الخارجة من جداول الدعم : 4 — كلُّها إلى support_staff / chat_threads
المحفّزات على جداول الدعم : 0
آخر تعديل بنيويّ على wallet / InternalEx / AccountsTb : أبريل 2026 — قبل المشروع
```

## الأدوار والصلاحيات — Default Deny في طبقتين

الدور **سقفٌ** لا منح. `ROLE_CEILING` تقول ما *يجوز* أن يناله صاحب الدور،
وصفوفُ `support_permissions` تقول ما *ناله فعلاً*. فمشرفٌ بلا صفوف لا يملك
شيئاً، وموظّفُ دعمٍ لا يُمنح إدارةَ الحسابات ولو ضغط المديرُ عليها بالخطأ.

| الدور | سقفُه |
|---|---|
| `SUPPORT_AGENT` | المحادثات المُسنَدة إليه وغيرِ المُسنَدة، الردّ، المرفقات، الصوت، تعديل رسالته، البحث، الاستلام لنفسه، تغيير الحالة |
| `SUPERVISOR` | ما سبق + رؤية كل المحادثات، الإسناد لغيره، الإغلاق وإعادة الفتح، التثبيت، التوجيه، السجلّ، الإحصاءات |
| `ADMIN` | الكتالوج كلّه — ويبقى محتاجاً إلى الصفوف |

**والإخفاء في الواجهة تجميل، والرفض الحقيقي في الخادم عند كل نداء** — مُثبَتٌ
باختبارٍ حيّ: موظّف دعمٍ عاديّ يعود بـ 403 على إدارة الحسابات ومنح الصلاحيات
والسجلّ والإغلاق والإسناد لغيره والتثبيت، ومحاولتُه تُسجَّل باسمه.

## حالات المحادثة

| الحالة | معناها |
|---|---|
| `NEW` | وردت ولم يستلمها أحد |
| `OPEN` | مُسنَدة ويُعمل عليها |
| `PENDING` | الدعم ردّ وينتظر الوكيل |
| `CLOSED` | أُغلقت |

**رسالةٌ من الوكيل تُعيد المحادثة إلى الحياة.** محادثةٌ أُغلقت ثم كتب فيها
الوكيل ليست مغلقة، وإبقاؤها كذلك يعني أن أحداً لن يراها في «المفتوحة» ولا في
«المُسنَدة إليّ» فتُنسى رسالتُه. الربطُ في `ChatController::send` — إضافةٌ فوق
الدردشة، لا ترمي شيئاً، وفشلُها لا يمنع وصول رسالة.

## العزل

`SupportController::thread()` تشترط `kind = ADMIN`، فمحادثةُ الوكيل مع
**موظّفه** لا تُفتح من المركز أبداً — لا بصلاحية ولا بدور ولا برقمٍ مخمَّن.
مُثبَتٌ حيّاً: محاولةُ فتح محادثة موظّفٍ ومحاولةُ الإرسال فيها كلتاهما 404.

والمرفقاتُ تُقدَّم لمن يجوز له فتحُ محادثتها وحده. الاسمُ عشوائيّ بأربعةٍ
وعشرين محرفاً، **والعشوائية ليست تصريحاً**.

## التشغيل

```bash
# 1) الجداول (خامل — تشغيلُه مرّتين لا يضرّ)
sqlcmd -S <SERVER> -d EXCHANGESYS2026 -i backend/database/sql/deploy/2026-09-06_support_center.sql

# 2) حساب المدير الأوّل — انظر آخر السكربت
cd backend && php artisan tinker --execute="…"

# 3) بناء الواجهة (Node على D:\tools\nodejs)
cd backend/support-app && npm install && npm run build   # ⇦ backend/public/support/

# 4) الصفحة
http://<HOST>/support
```

**التطوير:** `npm run dev` على المنفذ 5174، ويُمرَّر `/api` إلى Laravel على 8000.

## ⚠ أغلق الباب الخلفي

`/admin/chat` القديمة ما زالت تعمل بمفتاحٍ مشترك في `.env`، ومن يعرفه يقرأ
محادثات الوكلاء جميعاً ويردّ باسمِ من شاء **بلا دورٍ ولا صلاحيةٍ ولا أثرٍ في
السجلّ**. وهي بابٌ خلفيّ حول كل ما في هذا المستند.

```bash
# في backend/.env
CHAT_ADMIN_KEY=

php artisan config:clear
```

لم تُحذف شيفرتُها لأن إفراغ المفتاح قرارُ المالك، وحذفُها قبله يترك الإدارة
بلا صندوقِ واردٍ لحظةَ النشر.
