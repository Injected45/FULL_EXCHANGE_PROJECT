# تعديلات قاعدة البيانات

كل تعديل على مخطّط قاعدة البيانات يمرّ من هنا. لا يُنفَّذ أي تعديل مباشرةً على
الخادم دون ملف في هذا المجلد.

## لماذا مجلد منفصل ولماذا ليس `database/migrations/`

`database/migrations/` هو هيكل Laravel الافتراضي فقط (users, cache, jobs,
personal_access_tokens) وهو **لا يصف المخطّط الحقيقي**. قاعدة `EXCHANGESYS2026`
بُنيت خارج Laravel، و`App\Models\User` وحده يعتمد أعمدة (`phone`, `device_id`,
`UeserType`, `AccID`, `BrancchID`, `AccountType`) لا وجود لها في أي migration.

لذلك:

> **ممنوع تشغيل `php artisan migrate` بأي صورة.**
> `migrate:fresh` و `migrate:refresh` تحذفان جداول حيّة، و `migrate` وحدها ليست
> آمنة أيضاً. قاعدة البيانات هي المرجع، ومجلد `migrations/` زخرفة.

## القاعدة قبل أي تعديل

الترتيب المفضّل عند الحاجة إلى تغيير:

1. **المنطق أولاً** — عالج الأمر في الـ backend (Controller/Service) دون لمس المخطّط.
2. **جدول جديد** — إن لزم تخزين، أضف جدولاً جديداً مستقلاً. لا يكسر شيئاً قائماً.
3. **تعديل جدول قائم** — **يتطلّب موافقة صريحة قبل التنفيذ.** جداول المنظومة
   يشاركها تطبيق سطح المكتب و1041 روتيناً مخزّناً؛ تغيير عمود قد يكسر إجراءً
   لا يظهر في أي بحث نصّي.

## المحرّكان

الجدول نفسه موجود على محرّكين، ولكلٍّ نسخته:

| الطرف | المحرّك | الاتصال |
|---|---|---|
| `backend/` (Laravel) | SQL Server | `DB_CONNECTION=sqlsrv` |
| `ExchangeSystem/` (سطح المكتب) | MariaDB 10.4 أو SQL Server | حسب `DB_ENGINE` |

أي تعديل على جدول تقرأه المنظومتان يحتاج **نسختين**: `.sqlserver.sql`
و `.mysql.sql`. الجدول الذي ينفرد به التطبيق (جدول جديد لا يعرفه سطح المكتب)
يكفيه ملف SQL Server واحد — مع تدوين ذلك في رأس الملف.

## تسمية الملفات

```
YYYYMMDD_<وصف_قصير>/
  ├── up.sqlserver.sql      -- التعديل
  ├── up.mysql.sql          -- نفسه على MariaDB (عند اللزوم)
  ├── down.sqlserver.sql    -- التراجع — إلزامي
  ├── down.mysql.sql
  └── README.md             -- السبب، الأثر، ومن وافق
```

`README.md` داخل كل مجلد يجيب على:

- **لماذا** لم يكفِ المنطق وحده.
- **ما الذي يقرأ هذا الجدول غير التطبيق** (إجراءات مخزّنة، شاشات سطح المكتب).
- **الأثر على الصفوف القائمة** — و`down` هل يستعيد البيانات أم البنية فقط.

## بعد التنفيذ

- إن كان التعديل على MariaDB وأسقط روتيناً: أعد تشغيل
  `migration/apply_handports.sh` ثم `migration/audit.sh` — انظر
  [ExchangeSystem/migration/STATUS.md](../../../ExchangeSystem/migration/STATUS.md).
- `DROP PROCEDURE` يحذف صلاحية `EXECUTE` معه على الإنتاج؛ أعد منحها لكل كائن.
